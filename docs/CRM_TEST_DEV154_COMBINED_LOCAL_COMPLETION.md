## Corrected UAT-037 findings

- **G-02 / K-03:** Customer acceptance and the first exclusive reservation now commit in one
  database transaction. The generic negotiation-event route rejects standalone acceptance. The
  Booking transaction locks the Offer and Inventory, checks the current assignment and competing
  reservation before changing the Offer, and writes acceptance, negotiation evidence, Booking and
  reservation evidence together. A losing attempt changes nothing. Accepted Inventory cannot be
  delinked through the mutable-Offer shortcut.
- **G-06:** Initial reservation start and expiry are generated by the server as exactly seven days.
  Browser-supplied timestamps are ignored. Later change remains the governed Manager extension.
- **F-04:** An expired or ended assignment blocks Offer sending and revision as well as acceptance
  and Booking.
- **C-02 / P-05:** Administrative Inventory closure is restricted to the responsible team Manager
  and is rejected while any active reservation or unexpired assignment exists. Closure no longer
  silently terminates assignment rows.
- **B-04:** Every legacy `Under offer` Inventory migrated by 099 receives deterministic immutable
  audit evidence recording the original and derived statuses.
- **J / M:** Opportunity reassignment changes servicing ownership only. Offer identity, status,
  terms, revisions, customer communication and original `created_by` remain unchanged; the current
  servicing agent receives operating authority and the former agent loses it. Accepted/Reserved
  records do not block servicing reassignment.
- **J / M integration evidence gate:** `test/dev154-coordinated-reassignment.integration.test.js`
  performs a real HTTP POST against a dedicated migrated PostgreSQL fixture and verifies persisted
  Offer identity, Accepted status, current owner, immutable creator and absence of withdrawal evidence.
  It is intentionally not counted as passed in the local evidence because no dedicated PostgreSQL
  test database is configured on this workstation. Run it with `NYSA_RUN_DB_INTEGRATION=1` only
  against a disposable database whose name contains `test`, `fixture` or `ci`.
- **Q:** Opportunity and Inventory workspaces show current servicing agent, original assignment
  creator and original Offer creator, and separate active linkages from immutable history with
  lifecycle reasons and events.
- **O-03:** Confirmed as designed: a temporarily detached Deal points to an immutable `detached`
  linkage row. The pointer is not null, preserving timestamp, actor and reason evidence.
